# Орбита CRM

Учебная CRM на Nuxt 4: клиенты, сделки, задачи, дашборд. Бэкенд свой, на серверных эндпоинтах Nuxt — внешних сервисов не требуется.

## Запуск

```bash
npm install
npm run dev
```

→ http://localhost:3100

| Роль | Почта | Пароль |
|---|---|---|
| Руководитель | `admin@crm.ru` | `admin` |
| Менеджер | `anna@crm.ru` | `anna` |

Данные лежат в `.data/crm.json` и переживают перезапуск. Чтобы вернуть всё к исходному — удалить этот файл, он создастся заново из `server/data/seed.json`.

## Границы проекта

Код написан **только на том, что проходится в базовом курсе Vue + Nuxt**. Это сделано сознательно: проект должен читаться без гугления незнакомых API.

**Используется:**

`ref` · `computed` · `watch` · async/await · props · emit · `defineModel` · слоты · `onMounted` / `onUnmounted` · роутинг по файлам · динамические маршруты · лейауты · `NuxtLink` · `useFetch` · `$fetch` · SSR · Pinia · `server/api` · middleware

**Намеренно не используется:**

| Чего нет | Почему |
|---|---|
| слоты с параметрами (scoped slots) | таблица написана под клиентов, без универсальной абстракции |
| `Teleport` | `position: fixed` решает ту же задачу и понятнее |
| `Transition` / `TransitionGroup` | анимация появления делается обычным CSS `animation` |
| View Transitions API | эффект ради эффекта, много кода на ровном месте |
| `useState`, `useId`, `useRequestFetch` | хватает `ref` и Pinia |
| динамический `component :is` | два варианта через `v-if` / `v-else` читаются яснее |
| `toSorted`, `structuredClone` | обычные `sort` и `JSON.parse(JSON.stringify())` |

Единственное исключение — `useRequestHeaders(['cookie'])` в `stores/auth.js`. Без него авторизация ломается при SSR: на сервере `$fetch` не передаёт cookie сам. В файле это подробно расписано.

## Эндпоинты

```
POST   /api/auth/login              вход, ставит cookie
POST   /api/auth/register           регистрация, сразу входит
POST   /api/auth/forgot             выдаёт код для сброса пароля
POST   /api/auth/reset              меняет пароль по коду
POST   /api/auth/logout             выход
GET    /api/auth/me                 кто вошёл

GET    /api/stats                   метрики дашборда и график
GET    /api/search?q=               поиск для Ctrl+K

GET    /api/clients?q=&status=&sort=&page=
POST   /api/clients                 создать
GET    /api/clients/:id             клиент + сделки + задачи + история
PATCH  /api/clients/:id             изменить
DELETE /api/clients/:id             удалить вместе со связями

GET    /api/deals?owner=            сгруппировано по этапам
POST   /api/deals                   создать
PATCH  /api/deals/:id               сменить этап

GET    /api/tasks?filter=&owner=
PATCH  /api/tasks/:id               отметить выполненной
```

Метод задаётся суффиксом файла: `index.get.js`, `login.post.js`, `[id].delete.js`.

## Что посмотреть

**Ctrl + K** — поиск по клиентам, сделкам и задачам. Стрелки выбирают, Enter открывает. Один запрос на три сущности, с задержкой, чтобы не дёргать сервер на каждую букву.

**График выручки** на дашборде — обычный inline SVG. Все координаты считаются в `computed` из данных; библиотеки графиков нет.

**Кольцо конверсии** — один SVG-круг и приём со `stroke-dasharray`: длина штриха равна нужной доле длины окружности.

**Фильтры в адресе.** Выбрать фильтры на странице клиентов и скопировать ссылку — она откроется с теми же фильтрами. Работает и при SSR.

**Выгрузка в CSV** — собирается в браузере через `Blob`. Кавычки внутри значений удваиваются, в начало файла добавляется `﻿`, иначе Excel показывает кракозябры.

**Защита в двух слоях.** Выйти и вбить `/clients` — уведёт на вход. Затем в консоли браузера:

```js
await $fetch('/api/clients')
```

Вернётся 401: `requireUser` проверяет сессию на сервере. Это ответ на вопрос «достаточно ли гарда на фронте».

**Бизнес-правило на сервере.** Перевод сделки в «Выиграна» или «Проиграна» сам ставит дату закрытия, возврат в работу — снимает. Логика в `server/api/deals/[id].patch.js`, а не в компоненте: иначе при любом другом способе поменять этап правило бы не применилось.

**SSR.** Правая кнопка → «Показать код страницы» (исходник, не DevTools). Данные будут прямо в HTML.

## Дизайн

Холодная нейтраль и один акцент — как в рабочих системах вроде Linear и Attio. Насыщенность акцента ниже 70%: ядовитый синий — главный признак сгенерированного интерфейса.

- тени слабые и означают подъём слоя, а не украшают
- карточка в покое — только поверхность и волосяная граница
- цифры моноширинным с `tabular-nums`, чтобы колонки сумм выравнивались по разрядам
- анимируются только `transform` и `opacity`
- всё движение глушится под `prefers-reduced-motion`
- свои полосы прокрутки: системные на Windows выбиваются из палитры
- три состояния темы: авто / светлая / тёмная, выбор запоминается

### Скругления по смыслу

Радиус — не украшение. Шкала в `main.css`:

| Переменная | Где | Почему |
|---|---|---|
| `--r-block` 4px | панели, таблицы, карточки списков | часть раскладки, а не отдельный предмет |
| `--r-xs` / `--r-sm` 5–6px | кнопки, поля, плашки | мелкие элементы управления |
| `--r` / `--r-lg` 10–14px | модалка, палитра, выпадающий список, уведомления | лежат поверх страницы и должны читаться отдельным слоем |

Правило: чем ближе элемент к курсору, тем он круглее. Крупные области почти прямые. Раньше радиус 10px стоял вообще на всём — из-за этого интерфейс выглядел набором не связанных плиток.

### Показатели: у каждого своя визуализация

Четыре равные карточки в ряд — самый узнаваемый шаблон сгенерированного интерфейса. Причина глубже, чем рамки: композиция «подпись капсом → крупное число → подпись снизу» одна и та же для всех четырёх, потому что не зависит от того, **что** за цифра внутри.

`DashboardKpi.vue` даёт каждому показателю свой микро-график по смыслу:

| Показатель | Что добавлено | Зачем |
|---|---|---|
| Выручка | изменение к прошлому месяцу + линия тренда | голое число не говорит, много это или мало |
| В работе | составная полоса по этапам | видно, где застряли деньги |
| Клиенты | «+N за месяц» + состав базы | рост важнее абсолютного числа |
| Задачи | доля выполненных + просрочка | один процент вместо двух цифр |

Подписи обычным регистром: мелкие прописные в четыре ряда — ещё один признак шаблона. `MetricRow.vue` остался на карточке клиента, где показателей три и они однотипные.

### Даты подтягиваются к сегодняшнему дню

В `seed.json` даты записаны намертво. Через месяц после их написания дашборд выглядит мёртвым: выручка за текущий месяц ноль, половина задач просрочена, лента событий полугодовой давности.

`shiftToToday` в `server/utils/db.js` при первом создании базы находит самое свежее **произошедшее** событие и сдвигает все даты так, чтобы оно стало сегодняшним. Расстояния между событиями сохраняются.

Тонкость, на которой это сначала не работало: якорь нельзя считать по срокам задач — они специально лежат в будущем, и сдвиг выходил отрицательным. Считается только по созданию записей, закрытию сделок и истории.

### Этап сделки — стрелками, а не списком

На канбане выпадающий список ломался по двум причинам:

1. `.deal:hover` ставил `transform`, а **любой transform создаёт новый контекст наложения** — `z-index` списка перестаёт работать относительно соседей, и список уезжал под карточку, которая идёт ниже в разметке
2. доска со `overflow-x: auto` обрезает всё, что выходит за её границы

Лечить z-index бессмысленно: внутри контекста наложения ребёнок не может подняться выше родителя. Поэтому в карточке теперь две стрелки — переход на соседний этап. Ничего не выпадает, ничего не перекрывается, и клик один вместо трёх. На странице клиента список остался: там нет контейнера с `overflow`.

Свои контролы вместо системных там, где браузер рисует по-своему:

| Элемент | Чем заменён | Почему |
|---|---|---|
| `<select>` | `BaseSelect.vue` | список рисует операционная система |
| `<input type="checkbox">` | `BaseCheckbox.vue` | `accent-color` меняет только заливку |
| полосы прокрутки | CSS в `main.css` | на Windows это широкая серая колонка |

В `BaseCheckbox` настоящий `input` остаётся в разметке и становится прозрачным. `display: none` не подходит: так элемент выпадает из порядка табуляции и его перестаёт видеть скринридер.

## Доступность

- `:focus-visible` с видимой рамкой у всего интерактивного
- ссылка «К содержимому» первой по Tab
- `aria-current` у активной страницы, `role="radiogroup"` у выбора темы
- статус несёт не только цвет, но и точку-индикатор
- строки таблицы открываются с клавиатуры
- `sr-only` подписи у кнопок-иконок
